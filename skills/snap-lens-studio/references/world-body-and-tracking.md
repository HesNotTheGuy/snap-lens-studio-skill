# World, Body, Hand & Other Tracking

Tracking is how a Lens anchors virtual content to something real — the room around the user, their body, a hand, a printed image, or a famous landmark. Lens Studio exposes each of these as a **tracking component** (or a template built on one) that turns raw camera and sensor data into stable transforms your scene objects can attach to. Picking the *right* tracker is the single most impactful performance and UX decision in a world Lens: heavier trackers (World Mesh, Depth, 3D body/hand) unlock 6DoF placement and occlusion but cost battery and require capable hardware, while lighter ones (Rotation, 2D object tracking) run almost anywhere. This file covers the full tracking surface in Lens Studio 5.x and how to choose among the options.

> **Version pins (read first).** World Mesh 2.0 requires **Lens Studio 4.55+**. Current Lens Studio release is **5.23.1 (Aug 5, 2026)**. Spectacles targets are split: the **Spectacles (2024)** hardware is pinned to **LS 5.15.x** (currently 5.15.4, needs Snap OS 5.64.396+), while the newer **SPECS / 2026 glasses** run the **mainline 5.2x** line. Do not assume every Spectacles target is on 5.15 — verify Spectacles-specific APIs (World Query Module, SIK hand tracking) against the docs for the exact hardware you ship to.

## What is possible

- **World tracking** — anchor content to the environment in three modes: **Rotation (3DoF)**, **Surface** (the default, surface-anchored 6DoF), and **World** (free 6DoF via native AR).
- **World Mesh & Depth** — reconstruct the room as a real-time 3D mesh with optional surface classification, and sample a **Depth Texture** for occlusion and depth-aware effects.
- **Hit testing** — place content where the user taps/looks using instant world hit test, mesh ray casts, or physics ray casts.
- **Body tracking** — 2D and 3D skeletons (upper or full body), a deformable **Body Mesh**, gesture/touch/distance **triggers**, plus body segmentation and body morph.
- **Hand tracking & gestures** — 2D/3D rigged hands, per-bone skeleton controllers, and six built-in hand gestures.
- **Segmentation** — screen-space masks for person, hair, sky, body, garments, footwear, ground, and more.
- **Marker / image tracking** — anchor to a custom image or Snapcode.
- **Landmarkers & Location AR** — famous landmarks, city-scale authoring, and custom scanned locations with spatial persistence.
- **Object & pet tracking** — attach content to cats, dogs, hands, shoulders, and bodies.

## Key components, assets & APIs

- **Device Tracking** component (`DeviceTracking`) — lives on the **Camera** object; sets Rotation / Surface / World mode. World mode is required for World Mesh, Depth Texture, and instant hit test.
- **World Mesh** (with `Use Normals`, `Classification`) + **Depth Texture** asset. Script API: **`sceneReconstructionSupported`** (capability check) and **`hitTestWorldMesh()`** (mesh ray cast → position/normal/classification).
- **Physics `Probe.rayCast()`** (class `Physics.Probe`, created via `Physics.createGlobalProbe()`/`createProbe()`) — general physics ray cast. **Spectacles World Query Module** — lighter depth+normal hit test for wearables.
- **Object Tracking 2D** / **Object Tracking 3D** components — power body, hand, and object/pet tracking.
- **Full Body Mesh** asset + **Body Tracking Asset**; **Pin To Mesh**; **External Body Mesh**; **Body Depth and Normals** textures.
- **GesturesLibrary** / `MovementTrigger` (Full Body Triggers). Hand gestures: `registerDescriptorStart`, `onObjectFound` / `onObjectLost`.
- **Segmentation Texture** asset (mask type set in Inspector).
- **Marker Tracking** component (API class `MarkerTrackingComponent`) + **Image Marker** / **Snapcode Marker** assets.
- **LandmarkerController**, **HintController**, **FrontCameraMirror** (Location AR).

> Some exact API member names (e.g. `DepthTexture.sampleDepthAtPoint`, mesh classification format enums) were not individually re-confirmed against the Built-In API reference — check the API pages before hardcoding casing/namespacing.

## How to build it

**World tracking.** Select the **Camera**, add/adjust the **Device Tracking** component, and pick a mode. Docs confirm "By default, Surface mode is used." Use **Rotation (3DoF)** for skyboxes/360° panoramas (no walking). Use **Surface** to place an object on a floor or table — origin is a horizontal surface at the device's initial position; enable the **"Use Native AR"** toggle for enhanced tracking. Keep Surface content "roughly human size or less" since it does not detect walls or obstacles. Switch to **World** mode when you need free 6DoF movement, World Mesh, Depth, or instant hit test. See [tracking modes](https://developers.snap.com/lens-studio/features/ar-tracking/world/tracking-modes) and [world overview](https://developers.snap.com/lens-studio/features/ar-tracking/world/overview).

**World Mesh & Depth.** Put Device Tracking in **World** mode, then add a **World Mesh** ([world mesh & depth texture](https://developers.snap.com/lens-studio/features/ar-tracking/world/world-mesh-and-depth-texture)). Toggle **Use Normals**; enable **Classification** only on **LiDAR devices** — it labels faces as **wall, floor, ceiling, table, seat, window, door, and none**. Consume the **Depth Texture** in the Material Editor for occlusion. Always gate mesh access at runtime on `sceneReconstructionSupported` and provide a fallback.

**Hit testing.** For world placement, prefer **Instant World Hit Test** ([instant world hit test](https://developers.snap.com/lens-studio/features/ar-tracking/world/world-templates/instant-world-hit-test)): it hit-tests against the **Depth Texture** immediately at Lens start, then upgrades to a **World Mesh** hit test via callback once the mesh is available — so users don't have to "look around" first. For precise mesh casts use `hitTestWorldMesh()`; for general physics use [`Probe.rayCast`](https://developers.snap.com/lens-studio/features/physics/raycast). On **Spectacles**, use the [World Query Module](https://developers.snap.com/spectacles/about-spectacles-features/apis/world-query) instead — it is lighter than `hitTestWorldMesh`/`Probe.raycast` on wearables.

**Body tracking.** Use **Object Tracking 2D** for screen-space 2D body (efficient, with an upper-body option) or **Object Tracking 3D** for one or more 3D skeletons ([body overview](https://developers.snap.com/lens-studio/features/ar-tracking/body/overview)). **Upper Body Tracking 3D** exposes a subset of humanoid attachment points — "hips, spine bones, neck, head, shoulders, and upper arms" — and is meant for close-up/selfie subjects ([upper body tracking](https://developers.snap.com/lens-studio/features/ar-tracking/body/upper-body-tracking)). (For 2D image-to-joint work, the separate **Skeletal** template attaches images to 8 points: Head, Neck, Left/Right Shoulder, Left/Right Elbow, Left/Right Hand — [skeletal](https://developers.snap.com/lens-studio/features/ar-tracking/body/body-templates/skeletal).) **Full Body** (18 points) replaces the single Head joint with face points (Nose, Left/Right Eye, Left/Right Ear) and adds Hips, Knees, and Ankles; it needs the subject farther from camera. For a deformable mesh, add a **Full Body Mesh** asset with a **Body Tracking Asset**, set Hands/Body/Head checkboxes, and match **Body Index** to the paired Object Tracking 3D index (duplicate + bump the index per person). Use **Pin To Mesh** to attach content to the surface. The [Full Body Triggers](https://developers.snap.com/lens-studio/features/ar-tracking/body/body-templates/full-body-triggers) template offers three trigger types: **Gesture** (pose sequences via `GesturesLibrary`), **Touch Screen** (a joint enters a Screen Transform area), and **Distance** (joint-to-joint or joint-to-transform threshold), driving responses like Trigger Objects, Tweens, Animated Textures, Particle Bursts, or Behavior scripts.

**Hand tracking.** Use **Object Tracking 2D** or **3D** ([hand overview](https://developers.snap.com/lens-studio/features/ar-tracking/hand/overview)). The **3D Hand Tracking** component appends two rigged hand models; bundled prefabs are **Default 3D Hands, Frog 3D Hands, Skeleton 3D Hands** ([3D hand tracking](https://developers.snap.com/lens-studio/features/ar-tracking/hand/hand-tracking-templates/3d-hand-tracking)). Custom rigs must match the example rig — use the **Match Hierarchy** button to auto-map bones, or map manually. Use a **Hand Skeleton Controller** to append per-joint/bone models (Basic/Cartoony Bones) instead of a full rig. For gestures, register with `registerDescriptorStart` (gesture name + callback) or the Behavior "Descriptor Start" event, and handle `onObjectFound` / `onObjectLost` ([hand gestures](https://developers.snap.com/lens-studio/features/ar-tracking/hand/hand-gestures)).

**Marker tracking.** Add a **Marker Tracking** component to a Scene Object parented to the Camera, assign an **Image Marker** (custom PNG/JPG, **2048×2048 or less**) or a **Snapcode Marker**, and set **Marker Height** in physical cm ([marker tracking](https://developers.snap.com/lens-studio/features/ar-tracking/world/marker-tracking)).

**Landmarkers.** Add a bundled landmarker, keep its FBX reference mesh at native scale, choose a building render mode (Occluder / Semi-transparent / Custom Textures / None), and wire **LandmarkerController** + **HintController** ([location AR guide](https://developers.snap.com/lens-studio/features/location-ar/guide)).

## Best practices

- **Choose the lightest tracker that works:** Rotation < Surface < World for device tracking; 2D Object Tracking < 3D. World Mesh and Depth are heavy — reserve them for effects that truly need occlusion or reconstruction.
- **Gate heavy features** on `sceneReconstructionSupported` and always provide a fallback path so the Lens degrades gracefully on unsupported hardware.
- **Match Body Index** between the Body Mesh and its Object Tracking 3D component; for multi-person, duplicate the component and increment the index consistently.
- **Design marker art** to be high-detail, high-contrast, and non-repetitive so tracking locks reliably.
- **Segmentation quality:** use **ClampToEdge** on the Segmentation Texture to avoid edge tiling, layer two instances (feathered + refined) for clean outlines, and keep post-effect passes on the camera's render layer. Expect ML-based masks (Sky/Ground/Hair) to vary with lighting.
- **Pick the right person `SegmentationType`.** `PortraitSegmentation` is tuned for **close-up selfie/portrait** subjects (front camera, upper body large in frame). On a **back-camera / world / full-body** scene it degrades badly — the mask stops tracking the body and **bleeds onto bright regions** (sunlit floor, lights), so any effect keyed to it (heat fill, blur, recolor) spills far outside the person. For full-body, distant, moving, or multi-subject people — and for anything that must work on **both cameras** — use `SegmentationType.Body` instead; it masks close-up *and* full-body cleanly and holds tight under motion. **Verify the mask in the Preview with a moving, full-body clip** (e.g. the "One Person Dancing" / "Dance" preview videos on Back camera), not just a static portrait — a static selfie frame hides this failure because the subject *is* the bright foreground. **Polarity differs by model:** in a custom shader that samples the mask and lands the effect where the value is high, `Body` needs `InvertMask = false` (native person=1), whereas `PortraitSegmentation` in the same setup needed `InvertMask = true`. Flip it and re-check if the effect lands on the background.
- **Don't over-dilate a clean mask.** Dilating the mask (multi-tap `max`) to fill internal holes only makes sense for a *gappy* mask (e.g. PortraitSegmentation misfiring); on a clean `Body` mask it just pushes the effect **outward past the true silhouette** (fringe/spill). With a good mask, drop the dilation and use a slightly **inward** threshold (`smoothstep(0.45, 0.72, mask)`) so the effect stays inside the body edge.
- **Fix fast-limb dropouts with a TEMPORAL hold, not spatial dilation.** Any real-time person segmentation drops thin, fast-moving limbs (arms/hands) for a frame or two — motion blur + the model's own temporal smoothing lag below threshold — so a mask-keyed effect blinks off and looks cheap. Spatial fixes can't recover a fully-missing appendage; you need memory across frames. Add a **persistent feedback-loop RT** (`Clear Color = None`) written each frame with a fast-attack/slow-release envelope: `stab = max(seg_current, prev_stab * decay)` (decay ≈ 0.85 bridges ~5 frames at 30 fps), then read the *stabilized* RT instead of the raw mask. The effect keeps covering the limb through the dropout and the decay reads as an intentional motion-trail; because static background is `seg=0` it decays back to 0 (no permanent ghost). This is the same camera-feedback-loop plumbing as light-painting / paint-persistence lenses. Lower decay = tighter trail but less bridging; too high = laggy smear.
- On **Spectacles**, prefer the **World Query Module** over general ray casts, and use SIK hand tracking (`getHand` → `TrackedHand`, all 21 keypoints) for wearable interactions.

## Common pitfalls

- **Leaving Device Tracking in Surface mode** when the Lens needs World Mesh, Depth Texture, or instant hit test — these require **World** mode. This is the most common world-tracking mistake.
- **Using Full Body for close-up subjects** (or Upper Body for full-figure shots) — Full Body needs distance; Upper Body is for close-ups.
- **Rescaling or offsetting a Landmarker reference mesh** — the mesh must stay at native scale/position or alignment breaks. Also note the restriction, verbatim: "Landmarkers are not offered for commercial use, including advertisements and other promotional purposes."
- **Expecting multiple markers to track at once** — a Lens can register up to **10 marker images**, but **only one image is tracked at a time** (one image + one Snapcode can track concurrently).
- **Mismatched trigger names** — in Full Body Triggers, the string names must match exactly between `MovementTrigger` and the response scripts, or the trigger silently never fires.
- **Assuming "five" hand gestures** — the docs say five but enumerate six: `victory`, `open`, `index_finger`, `horns`, `thumb`, `close`. Treat the count as **six**; the "five" is a doc typo.
- **Enabling Classification on non-LiDAR devices** — mesh classification (wall/floor/ceiling/etc.) is LiDAR-only.
- **Expecting hand tracking to be reliable on Camera Kit** — docs warn it "may have limited compatibility and may not perform optimally."
